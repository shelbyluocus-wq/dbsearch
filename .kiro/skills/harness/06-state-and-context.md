# 状态记录与上下文压缩

长期 Agent 工作最容易失败的地方不是执行能力，而是状态漂移。

所以主 Agent 必须持续维护两类文档：

1. 项目状态记录
2. 续跑上下文包

## 项目状态记录

项目状态记录用于每一轮循环后的状态更新。

推荐模板：

- `templates/project-status-record.md`

必须包含：

- 用户目标
- 当前任务状态
- 当前轮次
- 已确认需求
- 当前假设
- 已批准计划
- 已完成内容
- 产出文件清单
- Bug 列表
- 已修复 Bug
- 未解决问题
- 下一步动作

## 状态枚举

当前任务状态只能使用以下值：

- 待计划
- 计划中
- 待执行
- 执行中
- 待测试
- 测试中
- 修复中
- 已完成
- 阻塞中

## 续跑上下文包

当任务执行时间较长、上下文变多时，主 Agent 必须主动维护续跑上下文包。

推荐模板：

- `templates/resume-context-package.md`

续跑上下文包的目标是让后续 Agent 不读取完整历史也能继续工作。

必须包含：

- 用户最终目标
- 当前阶段
- 已完成内容
- 当前产出文件
- 已确认设计决策
- 当前未解决 Bug
- 最近一轮测试结论
- 下一步应调用的 Agent
- 下一步任务包

## 更新规则

1. 每轮开始前，读取项目状态记录。
2. 每轮结束后，更新项目状态记录。
3. 每完成一个关键阶段，生成阶段总结。
4. 上下文过长时，输出续跑上下文包。
5. 不重复解决已经通过测试的问题。
6. 不遗漏历史上下文中的关键决策。
