## 二、Gitee 上需要创建什么

### 1. 创建仓库

在 Gitee 上创建仓库：**dbsearch-release**

地址：`https://gitee.com/shelbylouis/dbsearch-release`

### 2. 仓库结构

```
dbsearch-release/
├── latest.json          ← 更新索引文件（放在仓库根目录）
└── releases/            ← Gitee Release 页面，自动管理
```

### 3. latest.json 放在哪里

**方式 A（推荐）：放在仓库代码里，通过 raw 链接访问**

把 `latest.json` 提交到仓库的 master 分支根目录，访问地址为：
```
https://gitee.com/shelbylouis/dbsearch-release/raw/master/latest.json
```

### 4. 安装包放哪里

在 Gitee 仓库的 **Release** 页面创建新版本发布，把安装包作为附件上传。

## 三、latest.json 应该怎么填

```json
{
  "version": "5.1.0",
  "notes": "1. 新增自动更新功能\n2. 优化同步中心体验\n3. 修复已知问题",
  "pub_date": "2026-04-26T12:00:00+08:00",
  "platforms": {
    "windows-x86_64": {
      "url": "https://gitee.com/shelbylouis/dbsearch-release/releases/download/v5.1.0/鹰捷_5.1.0_x64-setup.nsis.zip",
      "signature": ""
    }
  }
}
```

### 字段说明

| 字段 | 说明 |
|---|---|
| `version` | 最新版本号，必须比当前版本大才会触发更新 |
| `notes` | 更新说明，会显示在更新弹窗里，用 `\n` 换行 |
| `pub_date` | 发布时间，ISO 8601 格式 |
| `platforms.windows-x86_64.url` | Windows x64 安装包下载地址 |
| `platforms.windows-x86_64.signature` | 安装包签名（见下方签名生成步骤） |

## 四、发布新版本的完整步骤

### 第 1 步：生成签名密钥对（只需做一次）

```powershell
npm run tauri signer generate -- -w ~/.tauri/dbsearch.key
```

运行后会提示：
- 输入密码（可以留空，直接回车）
- 生成两个文件：
  - **公钥**：`~/.tauri/dbsearch.key.pub` → 放进 `tauri.conf.json` 的 `plugins.updater.pubkey`
  - **私钥**：`~/.tauri/dbsearch.key` → 只在打包时用，**绝不要提交到仓库**

> ⚠️ 当前项目的公钥已经配置好了，你只需要保留好私钥文件。

### 第 2 步：修改版本号

1. 打开 `package.json`，把 `version` 改成新版本号，如 `"5.1.0"`
2. `scripts/sync-version.mjs` 会自动同步到 Cargo.toml 和 tauri.conf.json

### 第 3 步：构建带签名的安装包

```powershell
# 设置签名环境变量（每次打开新终端都需要）
$env:TAURI_SIGNING_PRIVATE_KEY = (Get-Content ~/.tauri/dbsearch.key -Raw)
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = ""   # 如果设置了密码就填

# 构建
npm run tauri build
```

构建完成后，在 `src-tauri/target/release/bundle/nsis/` 下会生成：
- `鹰捷_5.1.0_x64-setup.exe` ← 安装程序
- `鹰捷_5.1.0_x64-setup.nsis.zip` ← 更新用的压缩包
- `鹰捷_5.1.0_x64-setup.nsis.zip.sig` ← 签名文件

### 第 4 步：获取签名值

```powershell
# 读取签名文件内容
$sig = Get-Content "src-tauri/target/release/bundle/nsis/鹰捷_5.1.0_x64-setup.nsis.zip.sig" -Raw
Write-Host $sig
```

把输出的字符串填到 `latest.json` 的 `signature` 字段。

### 第 5 步：上传安装包到 Gitee

1. 打开 https://gitee.com/shelbylouis/dbsearch-release/releases
2. 点击「创建发行版」
3. 标签填 `v5.1.0`
4. 标题填 `鹰捷 V5.1.0`
5. 上传附件：`鹰捷_5.1.0_x64-setup.nsis.zip`
6. 发布

### 第 6 步：更新 latest.json

修改仓库中的 `latest.json`，填入：
- 新版本号
- 更新说明
- 下载地址（格式：`https://gitee.com/shelbylouis/dbsearch-release/releases/download/v5.1.0/鹰捷_5.1.0_x64-setup.nsis.zip`）
- 签名值

提交并推送到 Gitee。

### 第 7 步（可选）：同步到 GitHub

在 GitHub 仓库 https://github.com/shelbyluocus-wq/dbsearch 的 Release 页面也上传同样的文件，作为备用下载源。

## 五、私钥、公钥、签名文件分别放在哪里

| 文件 | 位置 | 用途 | 是否提交到仓库 |
|---|---|---|---|
| 私钥 | `~/.tauri/dbsearch.key` | 打包时签名用 | ❌ 绝不提交 |
| 公钥 | `~/.tauri/dbsearch.key.pub` | 已写入 tauri.conf.json | ✅ 已在配置中 |
| 签名文件 | 构建时自动生成，如 `*.nsis.zip.sig` | 填入 latest.json 的 signature | 填完可删 |

## 六、本地怎么测试自动更新

### 方法一：本地 HTTP 服务器模拟

1. 修改 `latest.json` 中的版本号为一个比当前高的版本
2. 在 `latest.json` 所在目录启动一个简单的 HTTP 服务器：
   ```powershell
   cd update
   npx serve -l 3210
   ```
3. 临时修改 `tauri.conf.json` 的 endpoints 为 `["http://localhost:3210/latest.json"]`
4. 运行 `npm run tauri dev`
5. 看到更新弹窗即为成功

### 方法二：直接在 Gitee 上发布测试

1. 在 Gitee Release 上传一个版本号更高的安装包
2. 更新 `latest.json`
3. 用当前的安装版（版本号较低）运行，看是否弹出更新提示

### 方法三：手动触发检查

在软件的设置页 → 「立即检查更新」按钮，可以随时手动触发更新检查。

## 七、更新流程说明

```
软件启动
  ↓
自动检查 Gitee latest.json
  ↓
Gitee 失败？→ 尝试 GitHub latest.json
  ↓
发现新版本？
  ↓ 是
弹出更新弹窗（显示当前版本、最新版本、更新说明）
  ↓
用户点击「立即更新」
  ↓
下载安装包（显示进度条）
  ↓
签名校验通过 → 自动重启应用 → 更新完成
  ↓
签名校验失败 / 下载失败 → 提示错误，可点「手动下载」
```

## 八、常见问题

**Q：Gitee 的 raw 链接在国内能直接访问吗？**
A：可以，Gitee 的 raw 链接不需要登录即可 HTTPS 访问，国内速度也很快。

**Q：Gitee Release 附件的下载链接格式是什么？**
A：`https://gitee.com/shelbylouis/dbsearch-release/releases/download/v版本号/文件名`

**Q：可以跳过签名吗？**
A：不建议。Tauri updater 默认要求签名校验，关闭签名会降低安全性。正确做法是用 `tauri signer` 生成密钥对，每次打包时签名。

**Q：安装包文件名有中文会有问题吗？**
A：Gitee 和 Tauri 都支持 URL 编码的中文文件名，但建议使用英文文件名更稳定。如果你要改文件名，只需确保 `latest.json` 中的 `url` 与实际上传文件名一致即可。

**Q：更新后应用会怎样？**
A：点击「立即更新」后，应用会下载安装包、校验签名、自动重启。整个过程不需要用户手动操作。
