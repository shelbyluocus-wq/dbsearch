# Bug 管理规范

Bug 必须始终使用统一编号。

## 编号格式

```text
BUG-001
BUG-002
BUG-003
```

## 状态

- 新增
- 待修复
- 修复中
- 待复测
- 已修复
- 无法复现
- 延后处理

## 严重程度

- P0：阻塞
- P1：严重
- P2：一般
- P3：轻微

## Bug 字段

每个 Bug 必须包含：

1. Bug ID
2. 严重程度
3. 问题描述
4. 触发条件
5. 判断依据
6. 影响范围
7. 建议修复方向
8. 当前状态

## Bug 表格模板

```md
| Bug ID | 严重程度 | 状态 | 描述 | 判断依据 | 建议 |
|---|---|---|---|---|---|
| BUG-001 | P1 | 待修复 | {描述} | {依据} | {建议} |
```

## Bug 修复规则

1. 测试 Agent 发现的问题必须先进入 Bug 列表。
2. 主 Agent 将 Bug 分派给执行 Agent 修复。
3. 执行 Agent 只修复任务包中的 Bug。
4. 执行 Agent 修复后必须说明每个 Bug 的处理方式。
5. 修复完成后必须进入测试 Agent 复测。
6. 测试 Agent 明确通过后，Bug 才能标记为已修复。
7. 连续两轮修复失败时，主 Agent 必须让计划 Agent 重新评估方案。
8. 连续三轮测试发现同类问题时，升级为架构/方案风险。
