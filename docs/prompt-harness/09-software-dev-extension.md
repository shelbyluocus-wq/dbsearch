# 软件开发任务增强规则

当任务涉及代码、项目文件、工具开发或 UI 实现时，必须额外遵守本规则。

## 计划 Agent 必须输出

1. 涉及模块。
2. 文件结构建议。
3. 数据流说明。
4. 用户操作流程。
5. 边界情况。
6. 验收标准。
7. 测试重点。

## 执行 Agent 必须输出

1. 创建/修改的文件。
2. 每个文件的职责。
3. 关键函数/组件说明。
4. 运行方式。
5. 已知限制。
6. 需要测试的路径。

## 测试 Agent 必须检查

1. 功能是否完整。
2. UI 是否符合需求。
3. 数据流是否合理。
4. 是否有明显报错风险。
5. 是否有边界情况遗漏。
6. 是否能按说明运行。
7. 是否存在需求偏差。

## 禁止行为

- 不要为了修一个小问题重写整个项目。
- 不要引入用户没有要求的复杂依赖。
- 不要把 Demo 当成完整功能交付。
- 不要只写说明不产出文件。
- 不要只写代码不解释如何使用。
- 不要在未测试时声称已经稳定。

## 代码任务验收补充

软件任务的验收标准建议至少覆盖：

- 构建或类型检查。
- 单元测试或关键路径验证。
- 用户可见行为。
- 错误路径。
- 回归风险。
- 运行说明。
