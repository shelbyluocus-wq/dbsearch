# 长时间运行控制规则

这部分用于防止任务越跑越偏、越修越乱。

## 防跑偏规则

1. 每轮开始前，先读取项目状态记录。
2. 每轮结束后，更新项目状态记录。
3. 不重复解决已经通过测试的问题。
4. 不因为新发现的小问题改变主目标。
5. 不擅自扩大任务范围。
6. 所有新增需求必须进入“待确认需求”或“下一阶段优化”，不能直接混入当前任务。
7. 连续两轮修复失败时，必须暂停执行并让计划 Agent 重新评估方案。
8. 连续三轮测试发现同类问题时，必须升级为架构/方案风险。
9. 每完成一个关键阶段，必须生成阶段总结。
10. 当上下文变长时，必须输出续跑上下文包。

## 循环控制规则

1. 每一轮必须有明确目标。
2. 每一轮只能解决当前范围内的问题。
3. 测试未通过时，不能宣布任务完成。
4. Bug 修复后必须重新交给测试 Agent。
5. 测试 Agent 只测试，不修复。
6. 执行 Agent 只执行和修复，不重新制定整体计划。
7. 计划 Agent 只规划，不执行。
8. 主 Agent 只调度，不执行。
9. 当连续 3 轮出现同类 Bug 时，必须升级为架构/方案风险。
10. 当上下文过长时，主 Agent 必须生成续跑上下文包，保证后续可以继续工作。

## 主 Agent 总控逻辑

```text
收到用户任务
↓
整理任务目标和上下文
↓
发送给计划 Agent
↓
计划 Agent 输出计划
↓
主 Agent 审核计划
↓
如果计划不合格 -> 返回计划 Agent 重做
↓
如果计划合格 -> 发送给执行 Agent
↓
执行 Agent 执行并产出文件
↓
主 Agent 记录产出
↓
发送给测试 Agent
↓
测试 Agent 测试
↓
如果测试通过 -> 主 Agent 输出最终总结，任务完成
↓
如果测试不通过 -> 主 Agent 整理 Bug
↓
发送给执行 Agent 修复
↓
执行 Agent 修复
↓
再次发送给测试 Agent 复测
↓
循环直到测试通过
```

## 完成标准

只有同时满足以下条件，主 Agent 才能宣布任务完成：

1. 用户目标已经实现。
2. 计划中的必要任务全部完成。
3. 执行 Agent 已提交最终产出。
4. 测试 Agent 明确表示通过。
5. 当前没有高优先级 Bug。
6. 当前没有阻塞性风险。
7. 产出文件清单完整。
8. 主 Agent 已生成最终总结。
